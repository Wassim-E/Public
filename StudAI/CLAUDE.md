# StudAI — Agent Guide

Student housing finder for Paris. Interactive map of ~300 residences from multiple sources, with commute time estimation, transit overlay, and Google reviews.

## How to run the pipeline

```bash
cd ml
pip install -r requirements.txt
playwright install chromium   # only needed for google_reviews

# Full run: scrape all sources + aggregate
python run.py

# Aggregate only (re-use existing debug/ files — fast, no network)
python run.py --aggregate

# Infrastructure only (stations + transit — rarely needed)
python run.py --infra

# Google reviews only
python run.py --reviews
python run.py --reviews --resume   # skip already-scraped IDs

# Per-scraper (from their own folder)
python studyrama/studyrama.py
python nexity_studea/nexity_studea.py
python action_logement/action_logement.py
python action_logement/action_logement.py --enrich  # re-enrich existing search results
python google_reviews/google_reviews.py --limit 3  # test on 3 residences (visible browser)
```

## Scraper conventions

Every scraper follows these rules:
- **tqdm** for progress bars on all network loops — explicit, visible progress
- **Blocking / synchronous** — no daemon threads, no background subprocess
- Phase headers printed before each stage: `[source] Stage N: ...`
- Output saved to `<source>/debug/<source>.json`
- Debug artifacts (screenshots, intermediate JSONs) go to `<source>/debug/`
- Do NOT re-run scrapers for data that already exists — they are slow (3–4 min for Studyrama, ~3 min for Nexity, Playwright for reviews)

## Data model

### housing.json (output of aggregator.py)

```jsonc
{
  "id": "studyrama-27280",
  "name": "ARPEJ Paul Cézanne",
  "lat": 49.04, "lng": 2.07,
  "provider": "Arpej",
  "category": "private",     // "crous" | "private"
  "type": "Résidence étudiante",
  "address": "12 rue ...",
  "description": "...",
  "imageUrl": "...",
  "images": ["..."],
  "amenities": ["WiFi", "Ascenseur"],   // canonical labels (see _AMENITY_PATTERNS)

  // Aggregated min/max across all price sources (used by filters)
  "rent": 329, "rentMax": 480,
  "surface": 14, "surfaceMax": 30,

  // Per-source pricing — one entry per scraper that found this residence
  "prices": [
    {
      "source": "studyrama",
      "sourceLabel": "Studyrama",
      "url": "https://...",
      "rent": 329, "rentMax": 351,
      "surface": 14, "surfaceMax": 23,
      "rooms": [{ "type": "Studio", "rent": 329, "surface": 14, ... }]
    }
  ],
  "sources": ["studyrama"],

  // Google Reviews (attached by aggregator from google_reviews/debug/)
  "googleRating": 4.2,
  "googleRatingCount": 85,
  "googleReviews": [
    { "author": "Alice", "rating": 5, "date": "il y a 3 mois", "text": "..." }

}
```

## Aggregation strategy

1. Each scraper writes raw data to its `debug/` folder
2. Aggregator normalizes each source (`_norm_studyrama`, `_norm_nexity`, `_norm_action_logement`)
3. Dedup + merge:
   - **Same source**: within 50 m AND same normalized name → merge
   - **Cross source**: same normalized name → merge (distance is unreliable across sources)
   - Canonical fields: prefer non-null, longer descriptions
   - `amenities`: union across all sources, normalized via `_AMENITY_PATTERNS`
   - `prices[]`: one entry per contributing source (no dedup within list)
4. Google reviews attached by matching on housing `id` (exact) or normalized name (fallback)

## Frontend architecture

- `App.tsx` owns: `filters` state (useReducer), `selectedHousing` state, `commuteMap`
- `HousingMap`: markers are `CircleMarker` (preferCanvas). Clicking a marker calls `onSelect(housing)`.
- `ResidenceDetail`: slide-in panel on the **left** (360px fixed). Shows prices, amenities, all reviews.
- `FilterSidebar`: fixed panel on the **right** (300px). Includes Google rating filter.
- Filter `minGoogleRating`: hides residences with no rating OR rating below threshold.

## Migrating existing debug files

After restructuring from `data_collection/` to `ml/`, copy existing raw files:
```bash
# Move raw scrape outputs to new debug/ folders
cp data_collection/raw/studyrama.json          ml/studyrama/debug/
cp data_collection/raw/nexity_studea.json      ml/nexity_studea/debug/
cp data_collection/raw/action_logement.json    ml/action_logement/debug/
cp data_collection/raw/action_logement_search.json ml/action_logement/debug/
cp data_collection/raw/google_reviews.json     ml/google_reviews/debug/
# Then re-aggregate:
cd ml && python run.py --aggregate
```

## Adding a new source

1. Create `ml/<source>/` with a `debug/` subfolder
2. Write `<source>.py`:
   - Use `tqdm` for all network loops
   - Output to `debug/<source>.json`
   - Print `[source] Stage N: ...` headers
3. Add `_norm_<source>(item)` to `aggregator.py`
4. Call `_load(...)` with the new normalizer in `aggregator.run()`
5. Add `import <source>.<source> as _<source>` and a run call in `run.py`
